## 2. CHRONOLOGICAL FOLDER ROUTING & INFINITE DAILY PAGE INDEXING
The application treats an individual shift timeline as a continuous sequential file folder capable of scaling to an unlimited quantity of pages per shift session:
* PAGE 1 (MANDATORY INGRESS): Permanently locked to Reporting For Duty (Form U-10.191). Persistent parameters (FTO/PO Badges, Phase bounds) are frozen across the entire phase block.
   - MUTABLE CONTROLS: The Cruiser ID input field is left as an editable plain-text string on Page 1. Shotgun training confirmations require a single-character velocity flag ("Y" / "N") for ultra-fast logging.
* SUBSTATION ORIENTATION HOOK (U-10.181): Triggers and mounts on 'Page 2' strictly ONCE on Day 1 of a new phase progression. Suppressed for all subsequent shifts in that phase.
* THE INFINITE RUN ARRAY CASCADE: Subsequent field run cards (U-10.182 through U-10.187) advance the page counter by exactly one integer indefinitely (Page 2, Page 3, Page 4, etc.).
* ATOMIC PHASE RESET LAUNCHERS: The moment an FTO terminates a shift (e.g., logging a final terminal entry at index W1D1P147) and initializes the next training date, the engine forcefully purges local index registers, resetting the new shift coordinate cleanly back to W1D2P1.

## 3. ALPHANUMERIC CLEARANCE MULTIPLIERS & AUTOMATED MULTI-CHARGE LOOPS
Selecting an alphanumeric clearance code token at the end of a shift run record dynamically injects pre-calculated transaction variables down the entire state machine:
* CODE 1V (Report and/or Citation Issued): Automatically applies a +1 increment to the shift's primary run type tally, and increments 'PremierOne Case Report' or 'Traffic Citations' (Solve Citation/Summons) based on content.
* CODE 2V (Party Advised, No Report Needed): Automatically increments the primary run type tally by 1, keeping case reports and citation counters at 0.
* CODE 3V (Arrest Made): Automatically apply an atomic batch increment of 1 across: 'U-10.100 (Arrest Information Form)', 'Prisoners Slated', 'Premier One Reports' (Case Report), and 'Probable Cause Affidavit'.
   - MULTI-CHARGE LOOP MECHANICS (N): For every separate individual criminal charge added by the FTO under Code 3V, instantiate exactly 1 distinct 'Criminal Complaint Form' payload into the local folder index array. Keep Misdemeanor vs. Felony selection as a quick one-tap toggle switch to keep metrics reconciled.
* CODE 4V (Non-Arrest Situation / Errand Completed): Logs execution timeline parameters strictly for forensic pathing.

## 4. FORM-SPECIFIC RATING CEILINGS & DEFICIENCY DE-DUPLICATION SCRIBES
Every checklist item maps directly into its broad block-level SEG performance matrix row. Checking an exception ('☐ unchecked') enforces immediate validation boundaries:
* THE PERFORMANCE CEILING CONSTRAINT: An unchecked checkbox category instantly forces a daily performance deficiency marker and mathematically caps that specific summary row, permanently blocking the probationary officer from receiving an automated weekly 'A' (Acceptable) rating.
* THE OFFICER SAFETY OVERRULE: Any single checked exception inside the Officer Safety sub-matrix (Categories 18–24 on your spreadsheet matrix layout) acts as an absolute daily override, locking the whole category row strictly to a non-negotiable 'UA' or 'RT' for that 24-hour shift block.

Example: (W3D2P3). FTO retains absolute manual authority to override and re-route the error to an alternative row via an override dropdown.

# Field Training Phase Timeline Notes

- Phase setup saves editable phase-week date ranges as consecutive Sunday–Saturday periods in the encrypted device workspace. Existing folders without ranges get defaults based on the current phase length.
- The verified standard schedule is 15 weeks: Phase I weeks 1–4 (4 weeks), Phase II weeks 5–8 (4 weeks), Phase III weeks 9–12 (4 weeks), and Phase IV weeks 13–15 (3 weeks). `artifacts/field-training/src/config/phaseConfiguration.ts` exports this 4/4/4/3 schedule through `PHASE_TIMELINE_REGISTRY.durationInWeeks`; Phase IV's fourth week is not enabled until the program duration is changed explicitly.
- FTO extension requests contain a target phase, extension type, requested week count, and unrestricted written justification. Requests are saved before success is shown; FTOs may continue paperwork while a request is pending.
- The FTO Coordinator reviews pending requests only after switching to the Coordinator role on the same device. Approval extends training weeks or extends the first Limbo period and moves later ranges. Denial removes the pending request. There is no cross-device sync, push notification, or server-side approval.
- Daily reports saved without a phase-week assignment while an extension is pending are assigned one after approval. Existing numbered reports remain snapshots.
- Monthly Excel output always has four weekly tabs. All selected monthly records are retained; source weeks beyond the fourth are consolidated in Week 4, whose date header identifies the extra weeks. Approved phase weeks beyond four are consolidated the same way.
- Do not alter the layouts or visual parameters of official printed forms U-10.173 through U-10.192 for phase timeline or extension changes.
