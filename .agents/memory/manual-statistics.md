---
name: Manual activity statistics
description: User rules for entering, reviewing, and aggregating activity metrics.
---

Statistics retain editable manual amounts. The user's newer instructions
authorize clearance-driven multipliers for new, completed and reviewed runs:
1V selects a case-report or applicable citation metric, 2V adds no report/citation,
and 3V adds arrest-report, prisoner-slated, case-report, affidavit, and per-charge
complaint counts. This supersedes the earlier blanket prohibition on code-driven
counts for those new runs, not for legacy saved accounting. Run activity flags
remain separate explicit selections.

The 3V multiplier applies only when the run records an arrest; 4V records the
timeline only and contributes no automatic activity counts. A newly recorded
transported arrest requires the actual destination before save.

For the user's current workflow, an arrest/3V record must be transported to
Jail, HQ, or Clerks; if no such transport occurs, use 1V instead of 3V.

**Why:** The user clarified that a 3V or recorded arrest requires transport and
that an arrest without transport should be recorded as 1V.

**How to apply:** When Arrest Made or 3V is selected, guide the FTO to a
transport destination. If the transport did not happen, allow the truthful 1V
path rather than saving a contradictory 3V/non-transport combination.

**Why:** The user defined 3V as “Arrest Made” and 4V as timeline-only, so a
clearance code must not create activity evidence that contradicts the recorded
run facts.

**How to apply:** Gate arrest counters and generated document drafts on the
recorded arrest fact, keep 4V out of automatic totals, and require a factual
destination for new transported-arrest records without rewriting legacy data.

The user requires categorical performance ratings only; do not introduce
numerical performance scores. Numeric values are appropriate for factual
activity totals and counts of categorical selections, not as a performance
grade or converted score.

**Why:** The user explicitly instructed that all requirements are strict and
numerical ratings are not used.

**How to apply:** Keep NO/A/RT/UA/NRT as the only evaluation outcomes. Do not
average, rank, or convert them to numbers; label numeric workbook values as
counts or totals.

**Why:** The user supplied explicit 1V/2V/3V multiplier instructions after the
manual-only rule. Existing saved totals may already include their older runs.

**How to apply:** Keep legacy runs from being silently recounted. Separate
manual amounts from derived contributions, prevent double increments on resave,
and do not present a generated payload as a completed or filed legal document.

Keep the portal's 30 named SEG categories, even when a reference form visibly lists 38 rows. The user reconfirmed the 30-category scope when asked about the mismatch.

**Why:** The user chose to keep the existing portal category model and later explicitly confirmed 30 categories for the workbook.

**How to apply:** Preserve the 30 named categories and keep the reference form's visual grouping separate from its legacy 38-row taxonomy. Do not expand or renumber the evaluation model without approval.

For a 10-6 Traffic Stop with 1V, do not count PremierOne/Axon; the FTO may select Solve Citation/Summons when applicable. Enforce that mismatch rather than silently changing a saved value. The user says 3V ordinarily means an arrest; if no arrest occurred, the FTO may correct the clearance/stat entries.

**Why:** The user explicitly required manual statistic entry and auditability, then asked for all metrics as run-level checkboxes and clarified the 10-6/1V mapping.

**How to apply:** Preserve explicit run flags and keep the distinct Traffic
Citations and Solve Citation/Summons columns separate; do not increment both for
one default citation event. Code-derived counts are user-directed prototype
automation, not independent proof of an operational event or legal filing.

Completion checklists on Reporting for Duty, primary run forms, required supplements, and Substation Orientation start checked for fast review. Not-applicable options start unchecked. Prefilled checklist selections are not confirmation; the FTO must review, clear inapplicable/incomplete items, and explicitly confirm the review. Activity-stat checkboxes remain unchecked because they represent events and counts, not expected actions.

**Why:** The user requested prechecked categories on all supplied forms while preserving correct statistics and review.

**How to apply:** Keep each supplied form's checklist on its own printable page with item-level checkboxes. Do not apply checklist defaults to statistical metrics.

On the editable Daily Performance Log, keep all SEG categories in one continuous, connected sequence with the activity-stat grid below the ratings. The print view follows the workbook's grouped columns.

**Why:** The user asked for an Excel-like daily log with connected rows and statistics at the bottom.

**How to apply:** Keep category names, definitions, and rating choices aligned consistently in the single screen sequence; keep the daily activity totals in connected groups beneath it.

The monthly Excel summary is a read-only rollup of reviewed, non-Limbo daily rating counts and saved activity totals. Keep it aggregate-only without raw incident IDs, locations, or narratives, and never write monthly totals back to daily records.

**Why:** The user requested a monthly export with all rating categories and monthly statistics, while keeping source daily logs distinct.

**How to apply:** Keep the export limited to the selected PO/month and clearly label weekly tabs and rating-frequency counts. Do not include raw run narratives or incident/location fields in the monthly workbook.

The user requires exactly four weekly Excel tabs with SEG and activity grids on
each. A month can span more than four Sunday–Saturday weeks, and no overflow
grouping rule has been approved.

**Why:** Silently dropping a fifth week or combining it with a different week
would misstate the source records.

**How to apply:** Fail explicitly rather than losing dates until a split or
overflow policy is approved. Do not change training-phase durations to fit tabs.
